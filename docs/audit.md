## 원문의 불명확한 표기

- 031 `$s`: 기술 요약에서 반복 표시의 닫는 괄호가 누락됩니다. 코드 자체는 매핑하지만 반복 제약을 추정하지 않습니다.
- 240 `$2`: 기술 요약에 반복 여부가 없습니다. 허용 식별기호로 매핑하되 반복 제약은 미확정입니다.
- 377 `$l`, 610 `$n`도 반복 표기가 불완전합니다. 기타 추출 불가 항목은 카탈로그의 `unresolved_summary_items`로 기록됩니다. 이 경우 허용 식별기호 목록을 닫는 검사를 자동 활성화하지 않습니다.
- 디렉터리 페이지 예시의 005 길이 `0016`은 005 본문의 14자리와 필드종단기호 1바이트를 합한 `0015`와 맞지 않습니다. 구현은 예시 수치를 하드코딩하지 않고 실제 인코딩 바이트 수에서 계산합니다.

## XML 매핑과 의미 검증은 별도

| KORMARC 요소 | XML 또는 처리 |
|---|---|
| 리더 24자리 | `m:record/m:leader` 원문 문자열; ISO 출력 시 길이·기본번지 재계산 |
| 디렉터리 표시기호 | 해당 `controlfield/@tag` 또는 `datafield/@tag` |
| 디렉터리 길이·위치 | 별도 XML 노드 없음; 출력 인코딩의 바이트 수로 재계산 |
| 00X | `controlfield`의 문자열, 공백과 위치 유지 |
| 나머지 필드 | `datafield`, 두 지시기호 속성, 순서 있는 `subfield` |
| 빈칸 지시기호 | 속성의 실제 공백 ` `; 화면의 `#`과 구별 |
| 반복 필드·식별기호 | 같은 XML 요소의 반복과 문서 순서로 보존 |
| 미등록·로컬 필드 | 동일한 일반 구조로 보존; 의미를 추정하지 않음 |
| FT / RT / SD | XML 요소 경계로 표현하며 ISO 출력 시 다시 생성 |

따라서 특정 의미 규칙이 아직 구현되지 않았다고 해서 그 필드의 XML 데이터가 누락되는 것은 아닙니다. 반대로 XML 왕복에 성공했다고 그 필드의 목록기술이 표준에 맞는 것도 아닙니다.

## 아직 완료되지 않은 검수

모든 필드 본문의 적용 조건·예외·필드 간 관계, X00–X30 공통 규정의 각 필드별 적용, 007/008 자료유형별 전체 자리 규칙, 006과 008의 대응 규칙, 부속서 부호표, 적용수준별 필수성, 부록의 제어 식별기호와 다문자 연결을 실행 가능한 규칙으로 완전히 검증하는 작업은 남아 있습니다. 소장용 규격으로 위임된 필드는 별도 규격 대조가 필요합니다. 설명과 예시에서 규칙을 자동 추론해 이 공백을 메우지 않습니다.

재현: 저장소 루트에서 `python scripts/audit_sources.py`, `python scripts/build_source_catalog.py`, `python scripts/activate_summary_rules.py`를 순서대로 실행합니다. 공식 페이지 개정으로 출력이 바뀔 수 있으므로 변경분 검토와 테스트 후 반영해야 합니다. 네트워크 없는 설치·CI는 이미 저장된 사실 카탈로그를 사용합니다.
