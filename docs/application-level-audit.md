# 적용수준·조건부 필수 규정 검수

2026-09-19. [표시기호별 적용수준](https://librarian.nl.go.kr/kormarc/KSX6006-0/sub/annex_9.html), [설계원칙](https://librarian.nl.go.kr/kormarc/KSX6006-0/sub/info_004.html), [리더](https://librarian.nl.go.kr/kormarc/KSX6006-0/sub/info_006.html)의 원문 캐시를 대조했다. 출처·SHA-256은 `resources/rules/application.json`에 기록한다. 필드별 M/A/O/- 값은 기존 `bibliographic.json`을 공동 사용하여 별도 필수 필드 목록을 중복 하드코딩하지 않는다.

부속서의 249개 필드 행을 원문 표와 대조하여 프로파일의 완전·최소수준 표시가 모두 일치함을 확인했다. 이 표 대조와 각 필드 본문의 조건·예외 검수는 별개다.

## 정상 검사로 반영한 범위

수준 3 검증은 리더/17이 실제 공백이면 완전수준, `7`이면 최소수준 표를 선택한다. 화면 표기 `b/`를 리더에 쓰지 않는다.

| 표시 | 의미 | 실행 동작 |
|---|---|---|
| M | 필수 | 해당 필드가 없으면 오류 |
| A | 해당시 필수 | 레코드 또는 호출자가 적용 조건을 확인한 경우 검사; 부재만으로 오류 판정하지 않음 |
| O | 재량 | 부재 오류 없음 |
| - | 최소수준 표의 표시 | 필드 사용 금지로 해석하지 않음 |

완전·최소수준 모두 **001·003·005·008·040·245·300**이 M이다. 필드가 존재해도 그 내용까지 올바르다는 뜻은 아니다. 예를 들어 빈 008은 존재 검사를 통과해도 길이 검사에서 실패한다. 리더는 기존 구조 검사, 디렉터리는 ISO 파서에서 검사하며 XML에 가짜 디렉터리 필드를 요구하지 않는다.

리더 본문에서 적용 조건을 직접 확인한 관계도 검사한다.

- 리더/07 `a`, `b`, `d`: 기본자료저록 773 요구.
- 리더/17 `4`: 목록작성 사업의 인증을 나타내는 042 요구. 사업명·인증 사실의 진위 검증까지 수행하지 않는다.

부재한 A 필드의 적용 조건을 확인하지 못한 경우 `application.applicability-unverified` 정보 진단에 미확인 필드 수를 표시한다. 이는 오류 개수나 전체 규정의 미완료 비율이 아니다. 모든 조건부 필수 규정을 자동 판정한다는 뜻도 아니다.

## 실물 확인 결과를 전달하는 방법

예를 들어 실물에 ISBN이 있어 020 적용이 필요함을 사서가 확인했다면, 해당 레코드에만 다음 프로파일을 전달한다.

```python
issues = validate(record, profile={"application": {"applicable_fields": ["020"]}})
```

CLI에서는 같은 내용을 JSON 파일로 저장하고 `kormarcxml validate record.xml --profile context.json`으로 실행한다. 여러 레코드에 하나의 프로파일을 쓰면 **모든 레코드에 같은 적용 사실을 선언**하게 되므로, 사실이 다른 레코드에는 개별 호출·프로파일을 사용한다. 이 목록은 ISBN 값을 생성하거나 필드를 보충하지 않는다. 이미 존재하는 020의 내용은 기존 규칙으로 별도 검사한다.

## KX-015 잠정 결정: 부속서 밖 입력수준

부속서는 리더/17 공백·7을 명시한다. `1`의 명칭에 완전수준이 포함되어도 공백 수준의 필수 표를 자동 확대하지 않는다. `1/2/3/4/5/8/u/z` 등에는 `application.level-unreviewed` 정보 진단을 내며, 해당 입력수준의 일반 필수 목록을 인증하지 않는다. 773·042처럼 본문에서 조건이 명시된 규칙과 나머지 기존 검사는 계속 수행한다.

잠정 방침은 **명시된 두 수준만 적용하고 다른 수준은 추정하지 않음**이다. 선택 이유는 소급변환·작성 중·발행 전 레코드의 완전성 요구를 혼동하지 않기 위해서다. 영향 범위는 부속서 밖 입력수준의 필수 필드 검사이며, 최종적으로 전문가가 수준별·사업별 프로파일을 결정해야 한다. KOLIS-NET 핵심수준을 완전수준과 동일하다고 가정하지 않는다.

## 검증과 한계

전체 테스트 **478개** 통과. 전용 테스트는 두 수준의 7개 필수 항목, 다른 입력수준, 조건 미확인, 호출자 확인, 최소수준의 `-`, 773·042, CLI, 수준 2와 3 분리, 원문 불변성을 검증한다. 기존 단일 필드 단위 테스트는 레코드 전체 필수성 진단과 분리하여 해당 필드 규칙을 검증한다.

합성 시연 레코드에 이전부터 빠져 있던 003·040을 명시적으로 보충하고 모든 시연 산출물을 재생성했다. 이는 운영 레코드 자동 수정 기능이 아니다. UTF-8·EUC-KR 및 6개 레코드 collection의 바이트 왕복이 유지된다.

공식 HTML 예제는 리더·고정필드 등이 없는 부분 예제다. 기존 합성 리더의 공백 입력수준 때문에 이번 검사에서 누락 진단이 늘지만 전송 왕복은 유지된다. 예제를 통과시키려고 필수 검사를 해제하거나 공식 예제 내용을 보충하지 않았다.

남은 검수는 각 A 항목의 전체 적용 조건·예외, 입력수준별 기관 정책, 880 의미 상속, 나머지 필드 본문 및 실제 운영 표본이다. 필수 7개를 확인했다고 전체 세부지침 검수를 완료한 것은 아니다.
