# 공식 예제의 전송 검증과 실제 표본 검증의 구분

검증 근거: [KORMARC 부록 D](https://librarian.nl.go.kr/kormarc/KSX6006-0/sub/appendix_d.html)의 로컬 HTML 원본. 결과·원문 SHA-256은 [기계 판독 보고서](../research/official-example-results.json)에 기록한다.

## 확인한 사실

부록 A–D를 확인했지만 완전한 리더·디렉터리·ISO 2709 바이트가 포함된 실제 운영 레코드 표본을 확보한 것은 아니다. 부록 D의 예제 7개 그룹은 원본 HTML에 존재하지만 **모두 상위 요소의 `display:none`으로 숨겨져 있다.** 일부 그룹에는 실제 문자 대신 `[... script]` 자리표시자가 있다. 따라서 현재 공식 화면에 공개되는 완전한 모범 레코드나 운영 데이터로 간주하지 않는다.

검증기는 기본적으로 숨겨진 예제를 제외한다. 이번 보조 실험은 `--include-hidden`을 명시하여 수행했다. 예제 본문은 저장소에 복제하지 않으며, 사용자가 확보한 원본을 로컬에서 읽고 통계·진단 식별자만 저장한다. 재사용 허락이나 프로젝트 라이선스를 공식 예제에 임의로 적용하지 않는다.

## 실행 결과

- 7개 그룹 중 6개, 총 73개 필드를 파싱하여 전송 실험을 수행했다.
- 표시용 `b/` 지시기호를 공백으로 해석하고, 식별기호 뒤 내용의 공백·결합문자·순서를 그대로 보존했다. Unicode 정규화는 하지 않았다.
- 원문에 없는 리더는 **실험용 합성 리더**로 명시적으로 추가했다. 리더의 실제 원래 값이나 원래 인코딩을 추정하지 않았다.
- 생성한 ISO → XML → XSD 검증 → 의미 검증 → HTML/tagged 표현 → ISO 왕복 및 6개 레코드 XML collection 왕복이 통과했다.
- 생성한 ISO 바이트는 왕복 후 동일하다. 이는 **원래 운영 ISO 파일과의 바이트 동일성**을 뜻하지 않는다. 원본에 없는 레코드 길이·기본번지·디렉터리는 생성 시 바이트 기준으로 계산했다.
- 그룹 1의 880에는 지시기호 하나가 빠져 있어 그룹 전체를 제외했다. 임의로 채워 넣지 않았다.
- 그룹 5의 과거 440 필드는 미검증 필드 진단, 그룹 6의 반복 066 `$c`는 현행 규칙의 반복불가 진단이 발생했다. 숨겨진 과거 예제에 맞추어 현행 규칙을 느슨하게 변경하지 않았다.

의미 검증에서 진단이 없다는 사실도 전체 서지적 적합성 인증은 아니다. 이 예제에는 필수요건 판정에 필요한 리더·고정길이필드 등이 빠져 있다.

## 재현

```sh
python scripts/verify_official_examples.py /path/to/appendix_d.html \
  --include-hidden --output research/official-example-results.json
```

프로젝트 설치 후 실행한다. 원문은 사용자가 별도로 확보하며, 스크립트가 네트워크로 취득하거나 원문을 배포하지 않는다. `--include-hidden`을 생략하면 숨겨진 그룹이 제외된 사실을 보고한다. 스크립트 자체의 테스트는 독립적으로 만든 짧은 HTML을 사용하므로 공식 캐시 없이 CI에서 실행된다.

## 남은 실제 표본 검증

공유 가능한 실제 운영 ISO 2709 표본이 아직 공급되지 않아 해당 검증은 **미수행**이다. 향후 자료유형별 표본, 실제 Leader/09와 문자 인코딩, 출처·재사용 조건, 오류 예상값을 함께 확보해야 한다. 그 표본으로 원본 바이트와 왕복 결과, 고정필드, 의미 검증 결과를 각각 비교한다. 현재의 합성 예제·공식 HTML 필드 그룹 검증으로 이 항목을 완료 처리하지 않는다.

2026-09-19 연결 검사 추가 후 같은 실험을 재실행했다. 전송 결과는 동일하며 그룹 5에 `linkage.6.peer-unverified` 경고가 추가되었다. 과거 440의 연결 규정이 현행 프로파일에서 미확인이므로 상대 필드가 없다고 단정하지 않는다.
